## Reproduce

Build the image with TV3's documented `make image`. Start Kafka, then use a fresh
topic and volume for exact counts. From the TV1 directory, supply an environment
file with the fresh topic and run `make init-topics seed`. Start the job:

```bash
docker run -d --name streamrag-tv2-integration --cpus 2 --memory 2g --network streamrag_default -u root -v streamrag_tv2_integration_lake:/lake -e KAFKA_BOOTSTRAP_SERVERS=kafka:29092 -e RAW_TOPIC=streamrag.tv2.integration.v1 -e LAKE_ROOT=/lake -e CHECKPOINT_ROOT=/lake/checkpoints -e 'TRIGGER=2 seconds' streamrag-stream-processor:dev
```

Wait for batch 0, then use the shared Makefile:

```bash
make simulate INGEST_ARGS="--event-file data/sample/live_events.jsonl --rate 10"
make simulate INGEST_ARGS="--edge-cases --rate 20"
```

Keep the same `ENV_FILE` and `PYTHON` overrides used for seed. After the batches
complete, mount the lake volume and `inspect_spark.py` from this directory into
another Spark container. Run it with `spark-submit --master 'local[2]'
--driver-memory 512m /verify.py`; its assertions check the totals above. The
inspection process exited 0. Counts assume a fresh volume and one replay only.

The test container was stopped after verification to release RAM; its volume is
preserved. Kafka remains available. This test does not cover MinIO/S3A, cleaned
topic output (not yet implemented in TV3), OpenSearch, `/ask`, or a second person's
clean-machine rehearsal. Those remain integration work for M1-09/10 and M1-17.
